=== Plan for rest parameters and the argument accessors

* Tests 5200 and 5201 now specify `NAME...` as the last parameter.  It
  binds `NAME` to the leftover positional arguments: in 5200,
  `args` is `[d,e,f]` and `$#args` is 3.

== 2026-11-19 18:19:14

=== Rest parameters, positional accessors, shift: implemented

* Signatures: `NAME...`, `NAME:TYPE...` and bare `...` as the last
  parameter, in both parsers.  Misplaced, defaulted, flag-prefixed or
  duplicate rest parameters, and unknown type names, raise
  `mcsh.syntax_error`.  Removed the dead `mcsh_signature_init_block`.
* Binding: command-line text is converted to the slot type (int,
  float, bool true/false/0/1); in calls, int converts to float and
  0/1 to bool.  Rest arguments are type-checked.  Too many arguments
  raises `mcsh.invalid_arguments` instead of a hard exit.
* `$0` function or script name; `$N` (raises if missing); `$+N`;
  `$#` count; `$@` list; `$*` word-split.  Positional only: not
  flags, flag values or name=value.  At top level they read the vm's
  argv; after `signature`, only the positional remainder.  Inplace
  and macro calls share the caller's arguments.
* New `shift [N]` builtin: returns true, or false after dropping all
  if fewer than N remain.  Only the shift counter changes.
* Fixed: on a binding error the call no longer leaves the stack in the
  callee's frame.
* Tests: un-skipped 5200 and 5201; 3204-signature-4 now passes; new
  5203, 5205-5210, 5212-5214; EXPECT lines added to 5204 and 3203.
  The four named-args/arg-extras unit tests had a backwards status
  assertion on an uninitialized status; fixed.
* README.adoc.m4 updated and regenerated with `./mk-doc.sh`.
* Not run locally: the full suite; it runs on GitHub.
* Found: `$?` is always 0.  `vm->exit_code_last` is set to 0 at
  startup and never updated, so the README claim that it is the last
  external command's exit code is wrong.  Only 5202 uses it, with no
  EXPECT.
